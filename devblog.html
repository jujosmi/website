CloneHeroAI: From Idea to Guitar Intelligence

Jujosmi Labs / PROJECT BLOG / STATUS: IN DEVELOPMENT

CloneHeroAI started as an experiment: could machine learning take a song file and turn the guitar performance into a playable five-fret Clone Hero chart? The answer turned out to be much harder than simply detecting sound and placing notes. The project has gradually become a guitar-understanding problem: separate the guitar from the rest of the song, understand what is being played, identify timing and musical events, and only then turn that information into a chart.

-- WHERE THE PROJECT IS NOW --
Current phase: Guitar Intelligence

We’re currently in Guitar Intelligence v0.8 postmortem/diagnostic stage. We successfully expanded the training data with Guitar-TECHS and completed a 24-epoch v0.8 training run, but validation performance collapsed compared with the v0.7 GuitarSet baseline, so we’re diagnosing the domain/generalization problem before building v0.8.1. The diagnostic script is now fixed and running to compare v0.7, v0.8-best, and v0.8-latest across the datasets.

UNUSABLE STAGE - Being developed toward a practical release.

DEV LOG 01 — THE IDEA STAGE 01

What if the chart could make itself?

The project began with a simple goal: take a song file and automatically turn the guitar part into a playable Clone Hero chart. Instead of manually authoring every note, the system would listen to the music and attempt to understand what the guitarist played.

That immediately created a much bigger problem. A song is not just guitar. It contains drums, bass, vocals, synths, effects and other sounds. If the system cannot tell those things apart, it cannot reliably know which sounds should become guitar notes.

DEV LOG 02 — EARLY CHARTING STAGE 02

The first attempts could make notes — but not necessarily the right notes.

Early experiments demonstrated the basic possibility of automatic chart generation. The system could output note patterns, but generating something that exists is very different from generating something that matches the guitarist.

The important lesson from this stage was that chart generation could not be treated as a simple pattern-making problem. The system needed information about the actual performance first.

LESSON: GENERATION IS NOT UNDERSTANDING
DEV LOG 03 — AUDIO2CHART STAGE 03

Establishing a baseline.

Audio2Chart became an important baseline for the project. It showed that a pipeline could go from audio toward automatically produced chart data, but it also made the weaknesses visible.

Timing was not good enough, and the generated patterns did not consistently behave like guitar charts. Having a working baseline was useful because it gave the project something concrete to compare against rather than trying to improve an undefined idea.

DEV LOG 04 — THE DRUM-LIKE CHART PROBLEM STAGE 04

One of the biggest turning points.

One of the most obvious problems was that some CloneHeroAI charts felt like drum charts instead of guitar charts. The model was finding rhythmic information, but rhythm alone is not enough to identify guitar playing.

This was the point where the project had to stop asking only "where are the sounds?" and start asking "which sounds are actually the guitar?"

PROBLEM IDENTIFIED: INSTRUMENT CONFUSION
DEV LOG 05 — ISOLATING THE GUITAR STAGE 05

Let the model hear the guitar first.

The pipeline began moving toward guitar-stem isolation before charting. The idea was straightforward: if the charting model receives a guitar-focused signal instead of the entire mix, it has a much better opportunity to learn the information that matters.

This also changed the architecture of CloneHeroAI. Rather than one giant step from song to chart, the system began becoming a pipeline: isolate → analyze → generate.

DEV LOG 06 — DATASET & TRAINING STAGE 06

Teaching the system what guitar actually is.

Training data became one of the most important parts of the project. The dataset work moved toward paired examples and tolerance-based matching so the model could learn from aligned audio/chart information.

Another important idea was the use of hard negatives. A guitar model cannot simply learn "loud musical sound = guitar." It needs to encounter drums, bass, vocals, synths and other material and learn that those sounds are not the guitar target.

The longer-term goal is for the model to work across different guitar tones, effects, techniques, playing styles and recording conditions rather than memorizing one kind of recording.

DEV LOG 07 — v0.5 → v0.6 STAGE 07

From recognizing guitar to understanding what the guitarist played.

Development increasingly focused on guitar intelligence rather than direct chart output. The system needs to understand pitch, onsets, timing, polyphony and playing techniques before it can decide which five-fret notes belong in the final chart.

v0.6 significantly improved pitch recognition. That improvement is part of the larger shift from "make a chart" to "understand the performance first."

DEV LOG 08 — v0.7 STAGE 08 — CURRENT

Turning guitar understanding into accurate events.

v0.7 is focused on the step between guitar intelligence and chart composition: accurate note events. The goal is to make sure the system knows when a guitar event happened and what that event represents before it starts deciding how to place it on a five-fret highway.

This stage is still considered part of the UNUSABLE STAGE. The project is not being treated as finished simply because the model can produce output. The output needs to correlate with the actual guitar performance.

DEV LOG 09 — CHART COMPOSITION STAGE 09 — NEXT

Understanding the performance is only half the job.

Once reliable guitar events exist, CloneHeroAI still has to turn them into playable five-fret charts. This is where musicality, difficulty, note selection, chords, rhythm and chart design become important.

The long-term objective is not merely to reproduce raw pitch information. It is to create a chart that represents the guitar performance while remaining appropriate for the Clone Hero format.

DEV LOG 10 — USABLE RELEASE STAGE 10 — GOAL

From research project to something players can actually use.

The final development stage is packaging the pipeline into a practical tool. That means reliable processing, playable output, testing on songs the system has not simply memorized, and enough polish that another Clone Hero player can use it without needing to understand the research behind it.

The project roadmap describes this as the USABLE RELEASE: turning the system into a practical tool that other Clone Hero players can use.
